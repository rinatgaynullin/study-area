# Vue

Используем eslint-plugin-vue в конфигурации `plugin:vue/recommended` и блюстим
официальное руководство по стилю. Но, кроме того:

**1.** Используйте Composition API для создания компонентов.

> [!IMPORTANT]
> Использование API опций допустимо только в крайних случаях - например, если этого требуют внешние зависимости.

**2.** Используйте шаблон `контекст + произошедшая операция` для именования пользовательских событий. Контекст опционален.

> [!WARNING]
> Контекст важен, но избегайте его избыточного использования. Имеет смысл явно добавлять его в имя события только когда
> он неочевиден из имени компонента, генерирующего это событие.

> [!TIP]
> В качестве ориентира рекомендуется использовать устоявшийся стиль именования нативных браузерных
> JS-событий.

```javascript
const emit = defineEmits([
  // Плохо - контекст должен стоять перед именем операции
  'submit-form',
  'update-user',

  // Плохо - мы не используем дополнительный префикс "on"
  'on-button-click',

  // Хорошо
  'user-update',
  'video-start',
  'homework-save-button-click',
]);
```

**3.** Используйте шаблон `[Контекст] + [Домен/Назначение]  + UI-тип` для
именования любых компонентов.

> [!INFO]
> Элементы схемы, заключенные в квадратные скобки, являются опциональными

- **Контекст** - имя родительского компонента. Используйте только для компонентов, тесно связанных
со своим родителем и не имеющих смысла в отрыве от него;
- **Домен/Назначение** - предметная область компонента и/или его целевая функция. Например, `Profile` в имени
`ProfileCard`, `HomeworkDelete` в `HomeworkDeleteButton` или `Underlined` в `UnderlinedLink`. Может отсутствовать в
именах базовых компонентов;
- **UI-тип** - общее примитивное название элемента пользовательского интерфейса, которым компонент фактически является
"в глазах пользователя". Доступны следующие стандартные типы:

  |          Тип          | Категория компонента                                                                                                                                                                                                                            |
  |:---------------------:|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
  | Общепринятое в UI имя | Базовый компонент                                                                                                                                                                                                                               |
  |         list          | Список чего-либо (карточек, тегов и т.п.)                                                                                                                                                                                                       |
  |        button         | Любой компонент, выполняющий какое-то действие при нажатии                                                                                                                                                                                      |
  |         text          | Блок текста (статичного или динамического)                                                                                                                                                                                                      |
  |        layout         | Глупый компонент с разметкой и слотами, выполняющий роль каркаса для какого-то контента                                                                                                                                                         |
  |         form          | Произвольный набор контролов для ввода данных или принятия решений, взаимодействие с которым изменяет состояние системы. Иначе говоря, любой компонент, выполняющий функцию веб-формы, вне зависимости от его реализации, сложности или размера |
  |         link          | Элемент (чаще всего текст), при нажатии на который происходит переход на другую страницу или скачивание файла                                                                                                                                   |
  |         image         | Любое изображение вне зависимости от способа реализации (будь то `<svg>`, `` или статичный `<canvas>`)                                                                                                                                     |
  |         table         | Табличное представление данных                                                                                                                                                                                                                  |
  |      composition      | Композиция элементов/компонентов/контента, выражающая определенную абстракцию, но не представляющая какой-либо явный UI-тип. Не злоупотребляйте этим типом, старайтесь использовать вместо него что-то более конкретное                         |
  |      Наследуется      | Компонент-обертка. Наследует тип оборачиваемого компонента - например, компонент `UserPhoneInput` оборачивающий `Input`, или `ProductDocumentLink` оборачивающий `UnderlinedLink`                                                               |
  |    Не используется    | Страница                                                                                                                                                                                                                                        |

**4.** Используйте слово `visible` при именовании логических свойств, которые отвечают за состояние
“видимости/невидимости” какого-то UI-элемента.

```vue
<template>
  <div v-if="isVisible">
    Безделье - игрушка дьявола

    <UModal v-model="isModalVisible" />
  </div>
</template>

<script setup>
  // Плохо
  const modalDisplayState = ref(false);
  const isModalDisplayed = ref(false);
  const isModalOpen = ref(false);
  const isModalShown = ref(false)

  // Хорошо
  const isVisible = ref(false);
  const isModalVisible = ref(false);
</script>
```

**5.** Не используйте инструменты веб-аналитики в
презентационных компонентах.

**Почему:**
Единственная задача "глупых" компонентов - отрисовка шаблона на базе входных параметров. Дополнительные сайд-эффекты,
связанные с бизнесом, усложняют их восприятие.

```vue [profile-card.vue]
<template>
  <UCard>
    <div>
      Имя: {{ props.name }}
    </div>

    <div>
      Фамилия: {{ props.surname }}
    </div>

    <UButton @click="onEditButtonClick">
      Редактировать
    </UButton>
  </UCard>
</template>

<script setup>
  import { analyticsService } from '@umschool/analytics';

  const props = defineProps(['name', 'surname']);
  const emit = defineEmits(['edit-button-click']);

  const onEditButtonClick = () => {
    // Плохо - размывает ответственность презентационного компонента
    analyticsService.track('profile_edit_button_click');

    emit('edit-button-click');
  };
</script>
```

```vue [student-profile-card.vue]
<template>
  <ProfileCard
    v-if="student"
    :name="student.name"
    :surname="student.surname"
    @edit-button-click="onEditButtonClick"
  />
</template>

<script setup>
  import {  onBeforeMount } from 'vue'
  import { ProfileCard } from './profile-card.vue';
  import { analyticsService } from '@umschool/analytics';

  const student = ref(null);
  const fetchStudent = () => { ... };

  const onEditButtonClick = () => {
    // Хорошо - веб-аналитике место среди остальной бизнес-логики
    analyticsService.track('profile_edit_button_click');
  };

  onBeforeMount(() => fetchStudent());
</script>
```
