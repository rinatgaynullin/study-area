# 17. Чертежи: `@rich-editor/drawings`

## Назначение

Чертёж — блочный атомарный узел `geometry` или `physics`. Источник истины —
JSON-сцена в формате PinQueen в атрибуте `data-geometry-data` /
`data-physics-data` и TikZ в `data-tikz-code`; картинка рисуется по сцене при
показе и в HTML не хранится. Пакет даёт редактору два узла, две кнопки
тулбара и диалог с конструкторами (а с опцией `json` — ещё с JSON, образцами, превью и TikZ), а вьюеру — лёгкий вход без
TipTap. Сцена хранится строкой как пришла: поля, которых рендер не знает, не
теряются.

```mermaid
flowchart LR
  json["JSON в data-*-data"] -- "parseSceneJson()" --> raw["объект"]
  raw -- "normalize*Scene()" --> scene["GeometryScene | PhysicsScene"]
  scene -- "render*Svg()" --> svg["SVG при показе"]
  scene -- "*ToTikz()" --> tikz["TikZ в data-tikz-code"]
```

## Когда использовать

- Геометрия: планиметрия (вершины, рёбра, углы, засечки, окружности),
  стереометрия (3D-вершины, сечения, цилиндры, конусы, шары, кабинетная проекция), графики
  функций (парабола, корень, гипербола, прямая, окружность, штриховка, точки).
- Физика: механика, термодинамика, электрические цепи, оптика — элементы с
  типом и координатами.
- Документы от распознавания: сцены приходят «грязными», нормализация
  принимает синонимы и старые форматы; битый JSON показывается плейсхолдером.

## Интерфейс

Сигнатуры — [14-api-reference.md](14-api-reference.md#rich-editordrawings).

### Подключение

| Где | Что | Вход |
| --- | --- | --- |
| Редактор | `createRichEditor({ features: [createDrawingsFeature()] })`, `<RichEditor :features>` | `@rich-editor/drawings` |
| Вьюер | `createRichContent({ features: [drawingsContent] })` или `createDrawingsContent({ locale })` | `@rich-editor/drawings/viewer` |
| Стили | Подключаются сами при импорте из исходников; для `dist` — `@rich-editor/drawings/styles.css` | — |

`createDrawingsFeature({ toolbarItems?: boolean, json?: boolean })`; подписи — `DRAWINGS_MESSAGES`
(ru, en), `messages` хоста их переопределяют. Заголовки карточек во вьюере
берутся из таблиц возможности по `locale` документной части.

### Формат узла

```html
<div data-geometry="true" data-geometry-data='{"type":"2d","vertices":{…},"edges":[…]}'
     data-tikz-code="\begin{tikzpicture}…" class="rte-drawing rte-drawing--geometry"
     role="img" aria-label="Чертёж"></div>
```

| Атрибут | Что хранит |
| --- | --- |
| `data-geometry-data`, `data-physics-data` | JSON-сцена строкой; узел читается и из `span`, и из `div` PinQueen |
| `data-tikz-code` | TikZ; генерируется диалогом из сцены, при импорте сохраняется |
| `aria-label` | Имя для читалки: «Чертёж» / «Физическая схема» |

Правила санитайзера — `DRAWINGS_SANITIZER_RULES` (пять атрибутов выше);
серверная копия — `DRAWINGS_ATTRS` в `rich_editor/sanitize.py`.

### Чертёж в документе

- Клик по чертежу без перетаскивания открывает его редактор. Раньше редактор
  открывался уже по нажатию, и перетащить чертёж было нельзя; теперь нажатие
  отдаётся редактору документа, а тап на тач-экране приходит тем же `click`.
- Чертёж перетаскивается мышью между блоками документа, `Alt+↑` / `Alt+↓`
  переставляют выделенный чертёж на один блок ([02](02-core.md#перенос-блоков)).
  В режиме «только чтение» чертёж не перетаскивается.
- `Enter` на выделенном чертеже открывает его редактор.

### Модель сцены

Геометрия (`GeometryScene`): `type` `2d | 3d | plot_2d` (правило типа — ниже;
без вершин, но с графиками — `plot_2d`),
`vertices` `{ A: [x, y] | [x, y, z] }`, `edges` (`from`, `to`, `style`
`solid | dashed`, `ticks` 0–4), `angles` (`points` — три вершины, вершина
угла вторая; `style` `right | single | double | triple`; `label`), `labels`
(положение буквы: `below left`, `above`…), `textLabels` (у середины отрезка
`position` со стороной `offset` или в точке `coords` мира), `sections`,
`cylinders`, `cones` и `spheres` (только 3D), `plots`, `angleY`/`angleZ`, `scale`, `offsetX`/`offsetY`,
`showGrid`, `showAxes`, `axes`.

Тела вращения (только 3D):

| Поле | Запись | Что рисуется |
| --- | --- | --- |
| `cylinders` | `{ base, top, radius }` | Цилиндр: центры оснований — вершины `base` и `top` |
| `cones` | `{ base, apex, radius }` | Прямой круговой конус: основание с центром `base` перпендикулярно оси `base → apex` |
| `spheres` | `{ center, radius }` | Шар с центром в вершине `center` |

`radius` по умолчанию 1. Запись с неизвестной вершиной не рисуется.

Тип сцены определяет `normalizeGeometryScene`: `2d` и `plot_2d` из `type`
остаются как есть; иначе сцена 3D, если у какой-то вершины ненулевая `z` либо
есть тело вращения (цилиндр, конус, шар), все вершины которого существуют, и
при этом нет `plots`. Раньше лежащий цилиндр и шар с центром в начале координат
(все `z = 0`) рисовались как 2D. Старые сцены читаются и рисуются как раньше.

Графики (`Plot`): `circle` (`center` или `centerVertex`, `radius`, `fill`),
`parabola` (`vertex`, `direction`, `stretchX`, `stretchY`, `domain`), `sqrt`,
`hyperbola` (`center`, `k`), `line` (`p1`/`p2` или `k`/`b`), `point` (`coords`,
`pointStyle` `solid | hollow`, `label`), `shading` (`points` или `bounds`),
`freehand`.

Физика (`PhysicsScene`): `elements[]` с `id`, `type`, `label` (LaTeX-подмножество:
греческие буквы, индексы, `\vec{}`, `\text{}`), `color`, `dashed` и геометрией
`points` / `center` / `coords`. Типы по разделам:

| Раздел | Типы |
| --- | --- |
| Механика | `surface` (`hatching`), `arc_surface`, `block` (`subtype` rectangle/circle/pulley, `angle`), `rope`, `spring`, `vector` (`vectorType` force/acc), `angle`, `stickman`, `balloon`, `ellipse_platform`, `dimension_line` |
| Термодинамика | `thermo_axes` (`xTicks`/`yTicks`), `thermo_point`, `thermo_process` (`subtype` line/isotherm/isochor), `piston_vessel` |
| Электричество | `circuit_component` (resistor/capacitor/inductor/switch/source/battery/voltmeter/ammeter/lamp/diode), `wire` (`wavy`), `charge`, `field_line`, `capacitor_plate`, `current_conductor`, `circle_shape` |
| Оптика | `lens` (converging/diverging, `focalLength`), `mirror`, `ray`, `optics_arrow`, `prism`, `glass_slab` |
| Общее | `text_label` |

### Нормализация

`parseSceneJson(text)` — терпимый разбор: ограждение ```` ```json ````, LaTeX-слеши
в строках, хвостовые запятые, одинарные и «умные» кавычки, ключи без кавычек,
комментарии; без `eval`. `normalizeGeometryScene(raw)` и
`normalizePhysicsScene(raw)` принимают что угодно и всегда возвращают сцену:
рёбра массивом, `{from,to}`, `{start,end}`, `{source,target}`; `circle`/`circles`;
`markings` как углы (без точек — пропуск); синонимы элементов `wall → surface`,
`weight`/`box` → `block`, `piston` → `piston_vessel`, `point` → `charge`,
`axis` → `vector`; группы `vessels`/`charges`/`vectors`/`elements`; старые
термографики `graph`, `graph_pV` и верхнеуровневые `thermo_*` с нормировкой
координат в окно 2..6 × 1.5..5.5; `splitEdgesThroughVertices` режет рёбра,
на которых лежит вершина. Подмены сцены `incline` шаблоном, как в оригинале,
нет: данные пользователя не выбрасываются. `detectDrawingKind(raw, hint?)`
отличает физику от геометрии по типу, термо-полям и элементам.

### Рендер и экспорт

| Функция | Что делает |
| --- | --- |
| `renderGeometrySvg(scene, { width?, height?, highlight?, autoFit? })` | SVG 300×300; слои: сетка → сечения → цилиндры → конусы → шары → рёбра → углы → окружности → вершины → подписи; `plot_2d` — оси, тики и графики |
| `renderPhysicsSvg(scene, { width?, height?, highlight?, autoFit? })` | SVG 340×300 со всеми типами элементов |
| `renderDrawingPreview(kind, scene, scale?)` | Превью карточки 340×300 с `autoFit`; `null`, если рисовать нечего |
| `geometryToTikz(scene)`, `physicsToTikz(scene)` | TikZ: 3D со `scale=3` и стилями hidden/visible (блоки «Конусы» и «Шары» рядом с цилиндрами), 2D с `\pic{angle}`, графики в `axis`; физика со `scale=0.5`, пружина `coil`, цепи в ключах circuitikz (`to[R]`, `to[C]`, `to[L]`, `battery1`…), изотерма гладкой кривой |
| `parsePgfplotsTikz(tikz)` | Сцена `plot_2d` из `\addplot`, если JSON нет |

Координаты: ось y вверх, масштаб 25 px на единицу (графики — 20); 3D —
поворот `angleZ`, затем `angleY`, затем кабинетная проекция (глубина под 45°
с коэффициентом 0.5). `autoFit` вписывает сцену в картинку: масштаб 12–120
для геометрии, 12–80 для физики; в расчёт входят и контуры тел вращения, в том
числе ободы цилиндров (раньше цилиндр мог обрезаться краем картинки). Линии и текст — `currentColor`, подложки
подписей и сетка — классы под тему; явные цвета элементов (силы синие,
ускорения красные, подсветка `#ec4899`) остаются.

Тела вращения рисуются так: у конуса видимая часть обода основания сплошная,
скрытая — пунктир, плюс две силуэтные образующие; у шара — силуэт и экватор
(скрытая половина пунктиром). Расчёт контуров — чистые функции `circle3d`,
`coneOutline`, `sphereOutline`, `visibilityRuns`, экспортируются из входов `.` и
`./viewer` ([14](14-api-reference.md#rich-editordrawings)). TikZ рисует сцену в
своём фиксированном виде: углы `angleY` / `angleZ` он не учитывает
([15](15-limitations-and-status.md)).

### Конструкторы

Диалог открывается почти на весь экран (`createModal({ fill: true })`, на
телефоне на весь) и показывает одну строку вкладок «Планиметрия / Стереометрия /
Графики / Физика». У нового чертежа вид (геометрия или физика) задаёт выбранная
вкладка; у существующего видны только вкладки его вида. Сцену открывает вкладка
подходящего конструктора. У каждой вкладки свой черновик, пока окно открыто:
переключение ничего не переносит и не стирает, вставляется рисунок активной
вкладки.

Окно открыто с `closeOnEscape: false`: `Escape` его не закрывает, закрывают
крестик и «Отмена». `Escape`, нажатый где угодно внутри окна, вызывает у
конструктора активной вкладки необязательный `SceneEditor.cancel()`: он бросает
незаконченное построение, возвращает инструмент «Выбрать» и снимает выделение;
сцена не меняется, недописанное значение в поле свойств не применяется. На
вкладке JSON `Escape` ничего не делает.

Опция `createDrawingsFeature({ json: true })` (по умолчанию выключена) добавляет
вкладку JSON, образцы сцен, предпросмотр и поле TikZ (в сворачиваемом блоке);
без неё пользователь работает только в конструкторе. С `json: true` текст JSON
заменяется рисунком только того конструктора, который пользователь менял, а
правленый текст загружается в конструктор, который его принимает. Вид нового
чертежа на вкладке JSON определяет сам текст: `type: 'physics'` или список
`elements` — физика; `type` `2d` / `3d` / `plot_2d` либо вершины, рёбра, графики —
геометрия, поэтому физическая схема, вставленная после вкладки геометрии,
остаётся физической. У существующего узла вид не меняется; пустой текст
принимает вид последнего конструктора.

Сцена, для которой нет конструктора, без `json` открывается со статусом «Этот
чертёж здесь изменить нельзя» (`drawings_unavailable`): сохранить нельзя, вид
узла не меняется. Нечитаемая сцена без `json` — чистое полотно и статус
`drawings_unreadable`. С `json: true` в обоих случаях открывается вкладка JSON с
исходным текстом.

Макет конструктора: слева полотно (`.rte-builder__stage`, занимает всё свободное
место; логический размер 560×420 масштабируется CSS), справа колонка шириной
`--rte-builder-side` (280px) с палитрой, свойствами и подсказкой; на узком
экране колонка уходит под полотно. Кнопки высотой 40px.

Значки кнопок — модуль `builders/builder-icons.ts`: `BUILDER_ICONS`,
`createBuilderIcon(id, size = 20)`, тип `BuilderIconId`. `ToolButton` принимает
`icon: BuilderIconId` (раньше `glyph: string`), `actionButton(label, icon,
onClick)` — id значка и даёт квадратную кнопку (`rte-builder__tool--icon`); у
`SceneEditorFactory` есть необязательное поле `icon` для вкладки. Палитра
элементов физики пока осталась на символах. Конструктор реализует
`SceneEditor` (`load(scene)`, `getScene()`, `onChange()`, `focus()`, необязательный
`cancel()`), а
подключается через `SceneEditorFactory` (`id`, `kind`, `labelKey`,
`accepts(scene)`, `create(context)`); `createDrawingsFeature({ editors })`
принимает свой список, по умолчанию — `DEFAULT_SCENE_EDITORS`.
`createDrawingsFeature({ scans: () => urls })` показывает сканы работы ученика
рядом с полотном.

| Вкладка | Что умеет |
| --- | --- |
| Планиметрия (`planimetryEditorFactory`) | Точки, отрезки, окружности (центр — точка `O`), углы (прямой — уголком), засечки 0–4, подписи у отрезков и в точке; перетаскивание точек с прилипанием к отрезкам, окружностям и сетке 0.5 (`Shift` отключает); панель свойств: имя и положение буквы, тип линии, засечки, длина и подвижный конец у отрезка, вид дуги, метка и величина угла, радиус и подпись окружности, текст; отмена и повтор (`Ctrl+Z`, `Ctrl+Y`), `Delete`, `Escape`, перемещение листа, зум колесом и жест двумя пальцами; точка на отрезке делит его сразу |

Подробно — [ниже](#конструктор-стереометрии) |

#### Общее управление полотном

Перемещение листа, масштаб и отмена жестов живут в общем полотне `SketchCanvas`
и одинаковы на всех четырёх вкладках.

- Нажатие основной кнопкой (или пальцем) по пустому месту полотно придерживает.
  Ушёл дальше 4 px — двигается лист; отпустил на месте — конструктор получает
  обычное нажатие (ставится точка, начинается отрезок, снимается выделение).
  Если под указателем объект или ручка, двигается он, а не лист; незаконченное
  построение (черновик отрезка, угла, штриховки) перемещение не сбрасывает.
  Исключение — карандаш в графиках: протяжка рисует штрих.
- Средняя кнопка мыши двигает вид, колесо масштабирует. Пока идёт придержанное
  нажатие, перемещение листа или жест двумя пальцами, колесо масштаб не меняет.
- Жест двумя пальцами: сведение и разведение — масштаб вокруг точки между
  пальцами (в пределах минимального и максимального масштаба полотна), сдвиг
  обоих пальцев — перемещение листа. Пока на полотне два указателя, конструктор
  событий не получает; после подъёма одного пальца оставшийся ничего не делает
  до отпускания.
- Стрелки в планиметрии, графиках и физике, пока ничего не выбрано, двигают вид
  на 0.5 единицы сетки; во время штриха и перетаскивания — нет. В стереометрии
  стрелки вращают фигуру.
- Вид (сдвиг и масштаб) — свойство только конструктора: в сцену он не пишется и
  шага истории не создаёт; картинка в документе вписывается по содержимому
  (`autoFit`).
- Курсор над пустым местом в инструменте «Выбрать» — `grab` (класс
  `rte-sketch--grab`), во время перемещения — `grabbing` (`rte-sketch--panning`).
- Подсказка инструмента «Выбрать» в планиметрии, графиках и физике говорит:
  «Тащи пустое место, чтобы подвинуть лист».

Отмена жеста не оставляет результата. Отменой считаются `pointercancel`,
потеря захвата указателя, появление второго пальца и `Escape`
(`SceneEditor.cancel()`): штрих карандаша отбрасывается, перетаскиваемый объект
возвращается туда, где был до жеста, отменённый поворот вида и жест ползунка в
стереометрии возвращают углы, шаг истории не остаётся (`HistoryStack.discard()`).
Обычное отпускание работает как раньше. `Escape` обрывает и перемещение листа.
Действие с клавиатуры, которое пишет историю во время незавершённого
перетаскивания (`Delete`, вставка, поворот стрелкой в стереометрии), сначала
завершает перетаскивание, как отпускание кнопки. Загрузка сцены сбрасывает
незавершённые жесты полотна (`SketchCanvas.resetGestures()`).

#### Конструктор стереометрии

Шаблоны (`STEREO_TEMPLATES`; панель «Шаблоны»). Основание лежит в плоскости
`z = 0` с центром в начале координат. Параметры — число в пределах 0.5–20 с
шагом 0.5; число сторон — целое от 3 до 8.

| Шаблон | Поля «Параметры фигуры» (значения по умолчанию) |
| --- | --- |
| Куб | «Ребро основания» (5) |
| Параллелепипед | «Длина» (6), «Ширина» (6), «Высота» (5) |
| Призма | «Число сторон основания» (3), «Ребро основания» (5), «Высота» (5) |
| Пирамида | «Число сторон основания» (4), «Ребро основания» (6), «Высота» (5.5) |
| Усечённая пирамида | «Число сторон основания» (4), «Ребро основания» (6), «Ребро верхнего основания» (3), «Высота» (4) |
| Цилиндр | «Радиус» (3), «Высота» (5.5) |
| Конус | «Радиус» (3), «Высота» (5.5) |
| Шар | «Радиус» (3) |

После вставки шаблона в панели виден блок «Параметры фигуры»: он перестраивает
фигуру, пока её геометрию не меняли вручную (сечения и углы остаются, если все
их вершины есть в новой фигуре). Шаблон заменяет сцену целиком, возвращает вид
по умолчанию (наклон 15°, поворот −30°) и вписывает фигуру в полотно. Вместо
пяти прежних шаблонов (две пирамиды, призма, параллелепипед, цилиндр) теперь
восемь, с параметрами.

Жесты в полотне:

| Жест | Что делает |
| --- | --- |
| Перетаскивание пустого места левой кнопкой мыши или пальцем | Двигает лист, как на других вкладках ([выше](#общее-управление-полотном)) |
| Перетаскивание правой кнопкой | Вращает фигуру: 0.8° на пиксель, наклон до ±85° |
| Ползунки «Наклон» и «Поворот», «Сбросить вид» | Вид числом (поворот −180…180°); сброс возвращает вид по умолчанию |
| Стрелки (пока ничего не выбрано) | Вращение на 5°, с `Shift` на 15° |
| Перетаскивание вершины, инструмент «Выбор» | Вершина едет в горизонтальной плоскости своей высоты с прилипанием к сетке 0.5 |
| То же с `Alt` | Вершина едет по вертикали (меняется `z`) |
| То же с `Shift` | Прилипание к сетке отключено |

Вращение и перетаскивание вершины пишутся одним шагом истории. Когда плоскость
видна почти с ребра, точка в пустоту не ставится и вершина по горизонтали не
двигается; по вертикали с `Alt` она не движется, если ось `z` видна с торца.

Высота новой точки: поле «Высота новой точки, z» в панели инструментов «Точка»
и «Отрезок». При ненулевой высоте оверлей показывает отвес до её проекции на
`z = 0`.

Невидимые линии: флажок «Невидимые линии — пунктиром автоматически» в блоке
«Вид». Пунктир считается по опорным плоскостям выпуклой оболочки вершин и тел
вращения (окружности оснований, шар) и пишется в `style` рёбер, формат сцены не
меняется. Флажок включён для новой сцены и шаблона; при открытии сцены — только
если расчёт совпал с сохранёнными стилями (чужую разметку молча не
переписывают); ручная смена стиля ребра его выключает. Тело считается выпуклым:
для невыпуклых построений флажок нужно выключить и расставить пунктир вручную.

Размеры. У выделенного ребра — поля «Длина» (в пространстве) и «Подвижный
конец»: выбранная вершина едет по прямой ребра, другая стоит на месте; значение
`≤ 0` и нулевое ребро сцену не меняют. У выделенной вершины, на которую
ссылается тело вращения (центры оснований цилиндра, центр основания и вершина
конуса, центр шара), — поле «Радиус» на каждое такое тело; радиус только
положительный.

Величина угла (планиметрия и стереометрия). Новый непрямой угол сразу подписан
своей величиной — «60°», дробная с одним знаком («63,4°»); в стереометрии это угол
в пространстве, а не угол проекции. Подпись пересчитывается при любой правке
геометрии: перетащили вершину, задали длину ребра, сменили параметры шаблона.
Прямой угол получает уголок без подписи. В панели выделенного угла — строка
«Величина» и флажок «Показывать величину на чертеже»: пока он включён, поле
подписи недоступно; выключенный оставляет подпись обычным текстом. Формат сцены
не меняется: величина пишется в `label`. При открытии сцены флажок включён, только
если подпись равна величине угла, — чужую подпись («α», «45°» на чертеже не в
масштабе) конструктор не трогает.

#### Конструктор графиков: блок «Функция»

У выделенной кривой (прямая, парабола, гипербола, корень, окружность) первым в
панели свойств идёт блок «Функция»: карточка формулы в школьной записи с
подставленными числами (`y = 2(x − 1)² − 3`, `y = 3/(x − 1) + 2`,
`(x − 1)² + (y + 2)² = 6,25`) и на каждый параметр ползунок, числовое поле и
короткое пояснение. Формат сцены `plot_2d` не менялся: формула выводится из уже
хранимых параметров кривой (модуль `builders/plot-functions.ts`, панель —
`builders/function-panel.ts`).

| Кривая | Формула и параметры | Ползунок |
| --- | --- | --- |
| Прямая | `y = kx + b` — `k`, `b`; вертикальная — `x = c`. У отрезка по двум точкам правка пересчитывает `y` точек, сами точки остаются | `k` от −5 до 5, шаг 0.1; `b`, `c` от −10 до 10, шаг 0.5 |
| Парабола | «Через вершину» `y = a(x − m)² + n` или «общий вид» `y = ax² + bx + c`; переключатель «Запись параболы». Выбор хранится в конструкторе, не в сцене | `a` от −5 до 5, шаг 0.1; `m`, `n`, `b`, `c` от −10 до 10, шаг 0.5 |
| Гипербола | `y = k/(x − m) + n` | `k` как `a` параболы; `m`, `n` как выше |
| Корень | `y = a√(x − m) + n`; переключатель ветви «вправо / влево» | `a`, `m`, `n` как выше |
| Окружность | `(x − a)² + (y − b)² = r²` — `a`, `b`, `r` | `a`, `b` от −10 до 10, шаг 0.5; `r` от 0.5 до 10, шаг 0.5 |

`a` параболы и корня нулём не бывает (наименьшее по модулю 0.05), `k` гиперболы —
тоже (0.1). Ползунок меняет график и формулу сразу; один жест ползунка — один шаг
отмены. Перетаскивание кривой по полотну обновляет формулу и значения параметров
на ходу. Вершина и растяжения параболы и точки отрезка хранятся в сцене с четырьмя
знаками после запятой (раньше двумя), чтобы коэффициенты общего вида не
«уплывали»; показ — два знака. Десятичный разделитель в формуле — ключ перевода
`drawings_decimal_separator`.

Флажок «Подписать график формулой»: поле `label` кривой равно формуле
(`y = 2(x - 1)^2 - 3`) и обновляется при каждом изменении этой кривой. Признак
хранится в конструкторе (с историей отмены), не в сцене; при открытии сцены он
включён у кривой, чья подпись уже равна её формуле. Ручная правка подписи признак
снимает; подписи других кривых не переписываются. В SVG степень в подписи графика
(`^2`, `^{…}`) рисуется верхним индексом; в TikZ десятичная запятая между цифрами
в математическом режиме оборачивается в `{,}` (`toLatexMath`) — это касается всех
подписей, не только графиков. Пока выделена кривая-функция, палитра шаблонов
сворачивается в одну строку кнопок-значков.

#### Палитра цвета и общие поля

В конструкторах «Графики» и «Физика» цвет выбирается сеткой из десяти плиток
(`DRAWING_COLORS` из `builders/color-picker.ts`, компонент `ColorPicker`, поле
`colorField`): синий `#2563eb`, голубой `#0891b2`, зелёный `#16a34a`, жёлтый
`#ca8a04`, оранжевый `#f97316`, красный `#dc2626`, розовый `#db2777`, фиолетовый
`#8b5cf6`, коричневый `#92400e`, серый `#64748b`. Списка названий и текстового
поля hex больше нет. Прежние значения (`#3b82f6`, `#10b981`, `#f59e0b`,
`#ef4444`, `#475569`) подсвечивают свою плитку как синонимы, сцена при этом не
переписывается. Цвет не из палитры, пришедший со сценой, показывается одиннадцатой
плиткой «Цвет из чертежа» (`drawings_color_other`) и сохраняется; кнопка «Обычный
цвет» убирает цвет. Палитра — `radiogroup`: одна плитка в порядке `Tab`, стрелки
переходят между плитками, `Home` / `End` — к первой и последней; выбранная плитка
отмечена рамкой и галочкой. Названия — ключи `drawings_color_*`; прежние
`drawings_plots_color_*`, `drawings_physics_color_*`, `drawings_plots_prop_hex` и
`drawings_physics_prop_color_custom` удалены.

Строки панелей свойств всех четырёх конструкторов строятся общими фабриками из
`builders/fields.ts`: `propsTitle`, `propsEmpty`, `textField`, `numberField`,
`checkField`, `selectField`, `pairField`, `sliderField`, `colorField`;
`propertyField` и `selectControl` по-прежнему экспортируются. Текст подписи
обрезается от пробелов по краям, пустой ввод в числовое поле игнорируется.

Общая основа для всех вкладок — `SketchCanvas` (слой сцены через общий
рендер и оверлей для черновиков, координаты мира, зум к курсору),
`HistoryStack` (снимок до изменения — одна отмена возвращает прошлое
состояние), `ToolBar` и подбор фигур `fitLine` / `fitCircle` / `fitParabola`,
`recognizeStroke` для карандаша.

## Пример

```ts
import { createRichEditor } from '@rich-editor/core';
import { createDrawingsFeature } from '@rich-editor/drawings';

createRichEditor({ element, features: [createDrawingsFeature()] });
```

```ts
import { createRichContent } from '@rich-editor/core/viewer';
import { createDrawingsContent } from '@rich-editor/drawings/viewer';

createRichContent({ element, html, features: [createDrawingsContent({ locale: 'ru' })] });
```

```ts
// Рендер вне редактора: сцена от бэкенда → SVG и TikZ.
import { normalizeGeometryScene, parseSceneJson, renderGeometrySvg, geometryToTikz } from '@rich-editor/drawings';

const scene = normalizeGeometryScene(parseSceneJson(text));
const svg = renderGeometrySvg(scene, { autoFit: true });
const tikz = geometryToTikz(scene);
```

## Ограничения

- Ручек изменения формы у графиков нет: растяжение, радиус и `k` правятся в
  блоке «Функция». У физических осей длины правятся числами.
- SVG в документе не хранится: вьюер без документной части вырежет узлы.
  Standalone-сборка и Django-виджет пакет пока не включают.
- `textLabels.coords` — координаты мира (в PinQueen это были пиксели).
- TikZ не компилируется в редакторе; это экспорт для бэкенда и LaTeX. Он рисует
  3D-сцену в своём фиксированном виде и углы `angleY` / `angleZ` не учитывает:
  вид, повёрнутый в конструкторе, в TikZ не попадает.
- Автоматический пунктир считает тело выпуклым; для невыпуклых построений
  флажок «Невидимые линии — пунктиром автоматически» нужно выключить и расставить
  пунктир вручную.
- Перенос чертежа на тач-устройствах полагается на встроенный механизм
  браузера и не проверялся.
